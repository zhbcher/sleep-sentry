# 守夜（SleepSentry）

用手机麦克风记录整夜睡眠声音的个人健康记录 App。
插上电、放床头、什么都不用做，第二天早上收到一份报告。

> **不是医疗器械，不做疾病诊断。**
> 本 App 依据麦克风采集到的声音推算"疑似呼吸暂停事件"的次数与分布，
> 无法反映血氧与中枢性事件，不能替代医院的多导睡眠监测（PSG/HSAT）。

---

## 它回答四个问题

| 问题 | 怎么做 |
|---|---|
| **什么时候憋的** | 精确定位到 0.1 秒，报告里可直接回听那一声 |
| **憋了几次** | 全程连续计时，一次不漏（这是选择"持续监听"而非"触发式"的原因） |
| **每次多长** | 每次事件的静默时长 |
| **严重到什么程度** | 每小时次数对标国际通用 AHI 分级刻度（<5 / 5–15 / 15–30 / >30） |

---

## 已验证到什么程度

核心算法在**合成音频金标准测试**上验证（7 种环境条件，含高噪声、电视干扰、长夜）：

| 指标 | 验收线 | 实测 |
|---|---|---|
| 事件召回 | ≥90% | **100%**（7/7 组） |
| 计数准确率 | ≥95% | **100%**（7/7 组） |
| 起点误差中位 | ≤0.5s | **0.04–0.18s** |
| 起点误差最大 | — | 0.16–2.38s（噪声越大越差） |

**真实数据验证（APSAA 数据集，32 人整夜录音 + 临床标注）**：
默认阈值下精确率仅 2.9%（17 命中 vs 563 误报），阈值扫描最佳 F1 35.7%。
**根因排查结论：不是算法的问题 —— 那份录音的麦克风离患者太远，
音频包络与临床鼾声标注相关系数只有 -0.012，五个频带的可分性全部低于阈值。
该数据集不适用于验证本方法**，详见 `dsp/GOLD_STANDARD.md` 的真实数据验证章节。

单元测试 20/20 通过（`./gradlew testDebugUnitTest`），含金标准 7 场景、环形缓冲、
PCM 流式写入的字节级一致性。

## 产品形态：为什么是"持续监听 + 择要留存"

早期设计曾采用"哨兵模式"（检测到异常才记录）。否决了，理由：

> 呼吸暂停的异常是**没有声音**。你没法对"没声音"触发录音 ——
> 必须先一直听着，才知道这段安静从什么时候开始、持续多久。
> 而且要回答"憋了几次"，必须一秒不落地连续计时；
> 触发式会漏数，漏了还无法区分"真没发生"和"没录到"。

**监听与保存必须解耦：要"数"的必须一直听，要"存"的才可以有选择。**

```
麦克风 16kHz 全程常开
  ├─ 实时累计（零落盘）：呼吸峰序列、静默段起止与时长、每秒信噪比
  └─ 择要落盘：事件前 10s + 后 5s / 每小时 1 个环境采样 / 手动收藏
```

单晚音频占用约 **3MB**（全量录音是它的 300 倍）。
环形池固定容量、旧数据自动覆盖 —— 用户一年都不用想"要不要清理"。

## 工程要点

| 点 | 做法 |
|---|---|
| 做到"每晚零操作" | 靠 `ACTION_POWER_CONNECTED` 广播拉起前台服务，**不用 App 自我后台唤醒**（安卓最不靠谱的做法） |
| 息屏不断录 | `PARTIAL_WAKE_LOCK` + 前台服务 `type=microphone` |
| 录不出底噪 | 依次尝试 `UNPROCESSED` → `VOICE_RECOGNITION` → `MIC` |
| **关闭 AGC** | 自动增益会抹掉鼾声的动态范围，而那正是要测的信号 |
| 断档自检 | 运行失败时记录具体原因并推送告知，**用户必须知道为什么没数据**（防静默流失） |
| 头号风险 | 国厂 ROM 后台限制。首次开启主动引导关闭电池优化 |

### 安卓版本约束

| 版本 | 要求 |
|---|---|
| API 28 (9) | `foregroundServiceType="microphone"` 必填 |
| API 29 (10) | 后台不能启动前台服务 → 必须用户点一次完成授权绑定 |
| API 33 (13) | `POST_NOTIFICATIONS` 运行时权限 |
| API 34 (14) | `FOREGROUND_SERVICE_MICROPHONE`；无 `RECORD_AUDIO` 直接抛异常 |
| API 35 (15) | 后台启动 mic 类前台服务抛 `ForegroundServiceStartNotAllowedException`；且**开机后禁止**自动启动麦克风前台服务 |
| 全部 | `microphone` 类型不受 Android 15 的 6h/24h 前台服务时长上限约束（待真机确认） |

## 构建

```bash
brew install openjdk@17                 # JDK 17
# Android SDK: cmdline-tools + platform-tools + platforms;android-35 + build-tools;35.0.0
echo "sdk.dir=$HOME/Library/Android/sdk" > android/local.properties

cd android
./gradlew testDebugUnitTest             # 11 个单元测试
./gradlew assembleDebug                 # 产出 app/build/outputs/apk/debug/app-debug.apk
```

安装：`adb install -r app/build/outputs/apk/debug/app-debug.apk`

```
sleepsentry/
├── dsp/                          Python 参考实现（算法规格书）

│   ├── run_gold.py               金标准对账测试
│   └── GOLD_STANDARD.md          实测结果 + 调试踩坑记录 + 已知局限
└── android/
    └── app/src/
        ├── main/kotlin/com/sleepsentry/
        │   ├── dsp/              核心算法（纯 Kotlin，无 Android 依赖，可 JVM 测）
        │   │   ├── Biquad.kt     RBJ 高通+低通（与 Python 逐行对应）
        │   │   ├── DspConfig.kt  阈值、噪声底、环形帧窗口
        │   │   ├── EventDetector.kt  流式事件检测
        │   │   └── Models.kt     事件/质量/严重程度分级
        │   ├── capture/          采集层
        │   │   ├── SentryService.kt      前台服务 + AudioRecord 主循环
        │   │   ├── RollingAudioBuffer.kt 环形音频缓冲（保证能切出事件前 10 秒）
        │   │   └── Receivers.kt          充电自启 / 开机恢复 / 早晨通知
        │   ├── store/            记录仓库（每日 JSON + 音频环形池）
        │   ├── ui/               主界面、时间轴、趋势图
        │   └── util/             配置、PCM 回放
        └── test/kotlin/          金标准测试 + 环形缓冲测试
```

**Python 与 Kotlin 两侧的阈值必须同步修改并各自跑测试，出现分歧即为回归。**

## 已知局限（诚实版）

1. **不重度打鼾的人群漏报率高** —— 方法靠"鼾声消失"观测气流中断，无鼾声则无信号。
2. **中枢性呼吸暂停检测不到** —— 无鼾声恢复期，与"安静睡觉"声音上无法区分。
3. **恒定环境噪声（风扇/空调嗡鸣）会掩盖鼾声** —— 这类噪声在能量上与"安静"无法区分。
4. **环境噪声突变可能被误计为事件** —— 已加"恢复性喘息必须是瞬态"判据压制，无法完全消除；
   报告提供原声回放让用户自行判断。
5. **超过 60 秒的静默一律不算事件** —— 更可能是人起身/翻出麦克风/录音中断。
6. **计时精度随环境噪声下降** —— 3 倍噪声下最大误差 2.38s，安静房间 0.05–0.2s。
7. **未做真实数据验证** —— 合成数据上的 100% 不等于家庭环境里的 100%。
